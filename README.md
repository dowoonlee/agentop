# agentop

여러 터미널 탭에 흩어진 **AI 코딩 에이전트 세션을 한 화면에서 보고, 바로 그 탭으로 점프**하는 macOS용 TUI입니다.

Claude Code · cursor-agent · codex 세션을 함께 잡아 상태·컨텍스트 사용률·브랜치·워크트리·모델을 한 줄에 모으고, 입력 대기(HITL)에 걸린 세션이 생기면 벨과 macOS 알림으로 알려 줍니다. 읽기 전용 모니터가 아니라 `⏎` 한 번으로 해당 iTerm2 탭에 포커스가 넘어갑니다.

```
🤖 2 ⚡ 1 🔭 3 🌐 2 🐳 4  │  📁 3 🌿 5/8  │  opus5 6 · sonnet5 2
↑↓ 선택   ⏎ 탭 점프   p 목록만   k 강제종료   r 새로고침   q 종료
  state act           ctx dir               worktree
━━ my-service ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
● busy  🔭 1🌐 1🐳 4  23% api               ⑂ feat-search
    └ ⎇ feat/search-ranking · opus5 · plan
◐ WAIT                41% web               ← 권한 승인
    └ ⎇ main · sonnet5
○ idle                 8% worker
    └ ⎇ develop · opus5
━━ infra ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
● busy  🤖 2          67% terraform
    └ ⎇ main · opus5
  ↳ hdls  ⚡ 1          12% eval5608/r1       ← 원문으로 발표자료 만들어…
      └ ↳ infra-b0 · fable5.1 · ⏵⏵bypass
───────────────────────────────────────────────────────────────
9 sessions  busy 5 · wait 1 · idle 2 · hdls 1   │  cpu 12%  mem 4.2GB
```

## 무엇이 보이나

세션 하나가 두 줄입니다.

- **1행** — 상태(`● busy` / `◐ WAIT` / `○ idle` / `⊘ stop` / `↳ hdls`), 활동 배지, 컨텍스트 사용률, 디렉터리, 워크트리(`⑂`), 상태 사유
- **2행** — 브랜치(`⎇`), 모델, 권한 모드

프로젝트(git 루트)별로 묶여 `━━ 이름 ━━` 구분선이 붙고, 그룹 순서는 세션이 늘고 줄어도 흔들리지 않습니다.

**활동 배지**는 `state` 바로 뒤 고정 슬롯에 섭니다 — 🤖 서브에이전트, ⚡ 백그라운드 shell, 🔭 Monitor, 🌐 로컬 서버, 🐳 compose 컨테이너. 앞 컬럼이 모두 고정폭이라 세로로 훑으면 지금 뭔가 돌고 있는 세션만 한 열에서 바로 잡힙니다. 뒤쪽 둘(🌐🐳)은 한 번 띄우면 계속 있는 것이라 자리가 덜 흔들리도록 끝에 뒀습니다.

cursor·codex 행도 같은 슬롯에 🤖🌐🐳를 답니다. ⚡🔭는 안 붙습니다 — 백그라운드 shell과 Monitor는 Claude Code transcript에서만 읽히는 값이라 이 둘에는 근거가 아예 없습니다.

**맨 윗줄 통계**는 전체 활동 합계(🌐🐳 포함), 📁 프로젝트 수, 🌿 워크트리 비율(전체 세션 중 워크트리에서 도는 수), 모델 분포입니다. 아래 footer는 세션 수와 cpu/mem을 맡아 위아래가 겹치지 않습니다.

🐳는 숫자가 둘일 수 있습니다. 컨테이너를 **자리**(compose의 `working_dir`) 단위로 갈라 세는데, 앞은 세션이 앉아 있는 자리의 컨테이너, 뒤는 **아무 세션도 없는 자리**의 컨테이너입니다. 둘을 가르는 건 **색뿐입니다** — 앞은 컨테이너색(탁한 파랑), 뒤는 hue가 반대인 탁한 벽돌색이라 `🐳 42`처럼 붙어 있어도 두 수가 갈립니다(귀속 4, 주인 없음 2). 세션은 끝났는데 `compose down`을 안 해 스택만 남은 경우가 대부분인데, 귀속될 행이 없으니 어느 배지에도 안 잡혀 화면에서 통째로 사라집니다. 둘을 더하면 compose로 뜬 실행 중 컨테이너 전부가 됩니다.

한 자리에 세션이 여럿이면 각 행이 그 자리 개수를 **그대로** 답니다(세션 2개가 나란히 `🐳 2`). 각 세션 옆에 자기 자리 스택이 보여야 하기 때문인데, 그래서 행 배지를 눈으로 더한 값은 통계와 다를 수 있습니다 — 통계는 자리 단위로 한 번만 셉니다. 귀속된 것이 하나도 없으면 앞 숫자를 빼고 `🐳 8`(벽돌색) 한 덩어리로 냅니다. `0`을 찍으면 그게 총계로 읽히기 때문입니다.

**codex가 낳은 서브에이전트**는 세션 행으로 세우지 않고 부모 행의 🤖로 접습니다. 이 자식(`codex app-server`)은 부모가 stdio로 물고 도는 프로세스라 부모의 tty를 그대로 물려받고, 그대로 두면 같은 세션이 목록에 두 줄로 섭니다. 게다가 자기 세션 기록(rollout)을 안 열기 때문에 그 줄에는 모델도 컨텍스트도 없어, 화면에서 가장 눈에 걸리는 정체불명 행이 됩니다. 부모는 프로세스 트리를 거슬러 찾습니다 — 사이에 Codex.app의 `node`·`node_repl`이 두어 단계 끼어 있어 `ppid` 한 칸으로는 안 닿습니다. 부모가 이번 목록의 codex 세션이 아니면(GUI나 플러그인이 직접 띄운 것) 아무 데도 안 셉니다.

**입력 대기 세션**은 `◐ WAIT` 빨강 배지로 강조되고, 새로 발생하면 벨 + macOS 알림이 뜹니다(`CC_TOP_NOTIFY=0`으로 끕니다). 목록 맨 위로 끌어올리지는 않습니다 — 자기 프로젝트 자리를 지킵니다.

**정지된 세션**은 `⊘ stop` 으로 한 톤 죽여 그룹 맨 아래에 둡니다. `claude agents --json` 은 프로세스가 SIGTSTP 로 멈춰도 마지막으로 보고된 상태(대개 `idle`)를 그대로 주기 때문에, agentop 은 `ps` 의 실제 상태를 봐서 덮어씁니다. 워크트리 진입처럼 세션이 프로세스를 갈아탈 때 원본이 이 꼴로 남으면 **같은 세션이 목록에 두 줄로 서는데**, 이 표시가 그 둘을 갈라 줍니다.

지우지 않고 남기는 이유는 멈춘 세션이 자식(MCP 서버·shell·좀비)을 물고 있어서입니다 — 정리할 대상이 있다는 건 보여야 합니다. `k` 를 누르면 SIGTERM 단계를 건너뛰고 바로 SIGKILL 로 갑니다(정지 중에는 SIGTERM 이 처리되지 않습니다). 프로세스 그룹 리더면 멈춘 자식까지 그룹째 정리합니다.

**headless 세션**(`claude -p`)은 사람이 앉지 않는 세션입니다. 평가 하네스나 배치 생성처럼 **다른 세션이 백그라운드로 낳는** 것이 대부분인데, `claude agents --json` 이 이런 세션의 상태를 안 실어 주고 작업 디렉터리도 대개 임시 폴더라, 손대기 전에는 이렇게 보였습니다.

```
━━ r1 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
· ?                   17% r1                (detached)
    └ ⎇ no-git · fable5.1 · ⏵⏵BYPASS
```

회차 디렉터리 `r1` 이 프로젝트로 승격돼 가짜 그룹을 만들고, 줄에서 가장 시끄러운 빨강 `BYPASS` 가 가장 뜻이 없는 자리를 차지하고, 정작 **누가 왜 띄웠나**는 어디에도 없습니다. 그래서 이런 행은 따로 다룹니다.

- **부모 밑으로 붙입니다.** 프로세스 트리를 거슬러 올라 자기를 낳은 세션을 찾고, 그 세션의 프로젝트 그룹 안 바로 아래 줄에 섭니다. 아이콘 `↳` 가 그 위 줄을 가리킵니다. 사슬이 끊긴 경우(중간 프로세스가 먼저 빠져 `launchd` 로 넘어간 자식)에는 scratchpad 경로에 박힌 부모 세션 ID로 한 번 더 찾습니다.
- **한 단 들여씁니다.** 부모보다 2칸 오른쪽에서 시작하고, 중첩되면 한 단씩 더 들어가 3단(6칸)에서 멈춥니다. 그만큼 뒤의 `act`·`ctx`·`dir` 열도 함께 밀립니다 — 열을 지키려면 들여쓰기를 1칸으로 줄이거나 `hdls` 글자를 빼야 하는데, 둘 다 '한눈에 자식으로 보인다' 를 잃습니다. 부모를 못 찾은 행은 들여쓰지 않습니다. 가리킬 위 줄이 없는데 들여쓰면 없는 소속을 지어내는 셈이라서입니다.
- **상태는 `hdls`** 입니다. `?` 가 아닙니다 — 상태를 못 읽은 게 아니라 보고할 쪽이 없는 것이고, 그 구분이 없으면 버그로 읽힙니다.
- **`-p` 로 던진 프롬프트**가 상태 사유 자리에 붙어, 이 세션이 무엇을 하는 중인지 한 줄에서 읽힙니다.
- **`bypass` 는 회색**입니다. 승인할 사람이 없는 세션이라 기본값에 가깝습니다. 지우지는 않습니다 — 여전히 무엇이든 할 수 있는 세션입니다.
- **디렉터리는 두 조각**을 씁니다(`eval5608/r1`). 회차 이름만으로는 아무것도 안 알려 주기 때문인데, 마지막 조각이 짧을 때만 그렇게 합니다.
- `(detached)` 는 안 붙입니다. 터미널이 없는 건 이 세션의 정의이지 사고가 아닙니다.

## 키

| 키 | 동작 |
|---|---|
| `↑` `↓` | 세션 선택 |
| `⏎` | 해당 iTerm2 탭으로 포커스 점프 |
| `p` | 배치 순환 — 2단 → 목록만 → 활동 → 2단 |
| `k` | 선택 세션 강제 종료 (SIGTERM → 잔존 시 SIGKILL, 확인받음) |
| `r` | 즉시 새로고침 (목록은 ~2초마다 자동 갱신) |
| `q` `ESC` | 종료 |

`p`는 세 배치를 돕니다.

| 모드 | 배치 | 쓸모 |
|---|---|---|
| **2단** (기본) | 좌 목록 / 우 상세 52% | 훑으면서 선택 세션의 요약을 같이 봄 |
| **목록만** | 전체 폭 | 디렉터리·워크트리·브랜치가 잘리지 않고 전부 나오며 dir 컬럼이 가장 긴 이름에 맞춰 정렬됨 |
| **활동** | 위 목록 / 아래 상세 72% | 선택 세션이 **무엇을 돌리고 어느 포트를 물고 있는지**를 상한 없이 펼침 |

**활동 모드**는 2단 패널에서 `외 N개`로 접히던 것들을 전부 폅니다 — 태스크 5개 상한과 서버 8줄 상한이 사라지고, 머리글도 한 줄로 줄여 세로 공간을 내역에 넘깁니다. 위아래로 나누는 이유는 서버·태스크가 세로로 긴 표라서입니다. 가로로 나누면 폭이 절반이라 컨테이너 이름과 명령 설명이 잘리는데, 위아래로 나누면 상세가 터미널 전체 폭을 씁니다. 목록은 세 모드 어디서나 위에 남습니다 — 모드를 바꿀 때마다 보던 세션 줄이 화면에서 옮겨 다니면 눈으로 다시 더듬어야 하기 때문입니다. 위쪽 목록은 좁아도 `↑↓`로 세션을 옮기며 아래를 보는 용도라 몇 줄이면 됩니다.

```
c2-15  #83995  ○ idle  ⑂ 5317-model-pricing-guard  ⎇ fix/5317-model-pricing-guard

tasks   2개 실행중
  ▶ 12s shell    격리 스택 기동 (백그라운드)
  ◉  3m monitor  PR #5326 리뷰·코멘트 감시 (10분 주기)

servers 1개 · 컨테이너 9개 (중지 1)
  🌐 19111 vite
  ✗ c2p5317-db-migrate-1       중지
  🐳 c2p5317-api-gateway-1      19116→8000
  🐳 c2p5317-frontend-dev-1     19111→5173
  …
```

`tasks`에는 **지금 돌고 있는 것만** 실립니다. 완료·실패·강제종료는 지나간 기록이라 현황판의 답이 아니고, 세션 하나가 하루에 태스크를 수십 개 띄우면 끝난 것들이 목록을 다 먹어 정작 살아 있는 하나가 상한에 밀려 안 보입니다(실측: 9개 중 실행 중 0개인데 9줄). 판정 기준은 목록 1행의 ⚡ 배지와 같습니다 — 이전 프로세스가 띄웠던 미완결 태스크도 부모가 죽으며 같이 끝났으므로 함께 빠집니다. 다 끝났으면 섹션째 사라집니다.

보드(🗂)와 마지막 지시(💬)는 활동 모드에서 뺐습니다. 파일 편집 이력과 사용자 지시는 '지금 돌고 있는 것'과 성격이 달라, 같이 담으면 이 화면의 초점이 흐려집니다 — 그쪽은 2단 패널이 맡습니다.

## 로컬 서버 — 어느 세션이 무엇을 띄웠나

dev 서버는 백그라운드 shell(⚡)과 알고 싶은 값이 다릅니다. 테스트나 CI 대기는 "끝났나"가 궁금하지만, 서버는 **"어느 포트로 열렸나"**가 궁금합니다. 그래서 배지를 나누고, 판정 근거도 나눴습니다 — ⚡는 transcript(기록), 🌐는 `lsof`(실물)입니다.

귀속은 **프로세스 조상**으로 판정합니다. 리스닝 포트를 물고 있는 프로세스에서 부모를 거슬러 올라가다 `claude`를 만나면 그 세션의 서버입니다.

```
node(vite) → npm exec vite --port 19111 → /bin/zsh -c → claude
```

명령 문자열을 패턴 매칭하지 않는 이유가 여기 있습니다. 실제로 세션이 실행한 명령이 `docker compose up --build`인데 그 안에서 vite가 뜨는 식이면, `vite|uvicorn` 같은 패턴으로는 영영 못 잡습니다. 조상 추적은 무엇을 어떻게 띄웠든 **결과로 열린 포트**만 봅니다.

덕분에 두 가지가 따라옵니다.

- **포그라운드로 띄운 서버도 잡힙니다.** 백그라운드 태스크가 아니라서 ⚡로는 안 보이던 것들입니다.
- **진짜 liveness입니다.** 서버가 죽으면 포트가 닫혀 배지가 바로 사라집니다. transcript 기반 판정은 종료 알림이 안 실리면 영영 '실행 중'으로 남습니다.

상세 패널에는 포트와 그것을 물고 있는 것의 이름이 나옵니다. `lsof`의 `COMMAND`는 `node`·`python3.1`이라 무슨 서버인지 안 알려 주므로, 명령줄에서 뽑습니다(`python3 -m uvicorn` → `uvicorn`, `node …/.bin/vite` → `vite`).

```
servers 2개 · 컨테이너 9개 (중지 1)
  🌐 19111 vite
  🌐 8100  uvicorn
  ✗ c2p5317-db-migrate-1   중지
  🐳 c2p5317-api-gateway-1  19116→8000
  🐳 c2p5317-frontend-dev-1 19111→5173
```

**Docker 컨테이너는 귀속 근거가 다릅니다.** 컨테이너 포트는 Docker 데몬이 물고 있어 세션의 자손이 아니고, 조상 추적으로는 영영 안 잡힙니다. 대신 compose가 컨테이너에 박아 두는 `com.docker.compose.project.working_dir` 라벨로 세션의 실효 cwd와 대응시킵니다 — `-p` 로 프로젝트 이름을 바꿔 띄워도 라벨은 compose 파일이 있던 자리를 가리키므로 워크트리별로 정확히 갈립니다.

경로가 정확히 같아야 하는 건 아닙니다. 세션의 실효 cwd에서 **위로 거슬러 올라가며 처음 만나는 compose 자리**에 붙입니다. 세션은 프로젝트 안을 돌아다니는데(`services/api`로 들어가거나, transcript의 마지막 cwd가 `node_modules` 깊은 곳일 때도 있습니다) compose 파일은 대개 루트 한 곳에만 있어서, 정확 일치로 두면 세션이 한 칸만 들어가도 배지가 떨어집니다. 자리가 중첩되면(본체에도 워크트리에도 compose가 있으면) **가장 가까운 것 하나**만 골라, 스택 하나가 두 세션 그룹에 겹쳐 세어지지 않습니다.

올라가는 길목마다 **그 밑 `.claude/` 한 칸을 먼저 봅니다.** `docker compose -f .claude/compose.test.yml up` 처럼 워크트리 전용 스택을 `.claude/`에 두고 띄우면 compose가 박는 라벨은 그 파일이 있던 폴더라, 세션이 앉는 워크트리 루트보다 **한 칸 아래**가 됩니다 — 조상 방향으로만 훑으면 자기 바로 밑의 스택을 영영 못 만나고 그 스택은 통째로 주인 없는 것으로 세어집니다. 내려가는 건 딱 이 한 칸뿐입니다. 임의 하위까지 열면 저장소 루트에 앉은 세션 하나가 모든 워크트리 스택을 빨아들입니다.

자리를 고를 때는 그 스택이 살아 있는지를 보지 않습니다. 세션 자리의 스택이 전부 죽었다면 배지는 안 붙고(`0`은 안 찍습니다) 상세 패널이 `중지 N`을 폅니다 — 여기서 살아 있는 상위 스택을 대신 집어 오면, 목록은 `🐳 2`인데 상세는 죽은 것만 보여 주는 모순이 됩니다.

목록에는 실행 중인 개수만 🐳 N으로 나가고, 이름·포트 매핑과 중지된 것은 상세 패널이 풉니다. 어느 세션에도 안 붙는 스택은 맨 윗줄 통계가 벽돌색 숫자로 따로 셉니다(위 참조). 라벨이 없는 컨테이너(손으로 `docker run` 한 것)는 어느 쪽에도 안 들어갑니다 — 세션과 무관한 시스템 전역 컨테이너까지 세면 숫자가 뜻을 잃습니다. **배지를 🌐와 합치지 않는 이유**는 둘이 다른 것이기 때문입니다 — 앞의 것은 세션이 띄운 프로세스라 `k`로 세션을 접으면 같이 죽지만, 뒤의 것은 데몬이 들고 있어 세션이 사라져도 남습니다. 한 숫자로 합치면 그 차이가 지워집니다.

`docker ps`는 데몬 상태에 따라 0.1초에서 몇 초까지 늘어져 2초 폴링에 직접 넣을 수 없습니다. 그래서 **목록은 캐시만 읽고 갱신은 백그라운드로 돌립니다** — 배지가 최대 `CC_TOP_DOCKER_TTL`초 늦게 붙는 대신 폴링은 절대 밀리지 않습니다. 컨테이너는 dev 서버처럼 오래 떠 있는 것이라 그 지연이 읽는 데 지장을 주지 않습니다. 상세 패널은 세션 하나를 그리는 자리라 캐시가 낡았으면 거기서 기다려 채웁니다.

중지된 컨테이너를 목록 위에 올리는 것도 의도된 순서입니다. 스택이 열 몇 개면 상한에 걸려 뒤가 잘리는데, 그때 잘려서 안 될 것은 떠 있는 아홉 개가 아니라 **죽은 하나**입니다.

목록 폴링에 더해지는 비용은 `lsof`+`ps` 각 1회로 ~0.15초이고, 세션 수와 무관합니다(맵을 루프 전에 한 번 만들어 문자열로 넘깁니다). 상세 패널은 `gen`이 이미 구한 포트를 스냅샷에서 받아 다시 훑지 않습니다.

## 세션 보드 — 같은 저장소의 세션끼리 서로를 알게 하기

한 저장소에서 세션 열 개가 동시에 돌면 "누가 무엇을 하고 있나"를 알 방법이 상대 세션에게 **묻는 것**밖에 없습니다. 물어보는 쪽은 기다리고, 물어보는 대상은 방해받고, 세션이 늘면 그 비용이 제곱으로 늘어납니다.

세션 보드는 그 방향을 뒤집습니다. 각 세션이 자기가 고친 파일을 훅으로 자동 기록하고, 읽는 쪽은 파일만 봅니다. **질문은 0회입니다.**

```
./install.sh --hooks        # 훅 3개 등록 (새로 시작하는 세션부터 적용)
./install.sh --unhooks      # 되돌리기
```

| 훅 | 시점 | 하는 일 |
|---|---|---|
| `board-record.sh` | PostToolUse (`async`) | 방금 고친 파일을 자기 보드 파일에 한 줄 append |
| `board-gate.sh` | PreToolUse | 고치려는 파일을 다른 세션이 최근에 만졌으면 알려 줍니다 |
| `board-brief.sh` | SessionStart | 같은 저장소의 다른 세션을 요약해 새 세션 컨텍스트에 얹습니다 |

**세션 시작 시 주입되는 브리핑**은 이런 모습입니다 — 상대 세션의 마지막 지시(의도)까지 붙습니다.

```
## 같은 저장소의 다른 세션 (agentop 세션 보드)

- c2-a5(15e60983) [busy] · 워크트리 4918-log-encryption-cleanup · 마지막 편집 54초 전
  의도: 별도 이슈로 분리하고 담당자 moon-1c로 해줘
  최근 편집: docs/specs/conversation-log-encryption.md
- c2-fa(902e94f8) [busy] · 워크트리 4862-vw-refresh-stage-promote · 마지막 편집 3분 전
  의도: 검토하고 문제 없으면 커밋하고 pr 올리고 진행해
  최근 편집: services/c2-vw-service/app/agent/hub_pins.py · tests/test_hub_pins.py
```

**편집 직전 충돌 알림**은 두 등급을 구분합니다. 같은 저장소에 워크트리가 여럿일 때 이 구분이 값어치입니다.

- **같은 체크아웃** — 절대경로가 같습니다. 서로의 편집을 실제로 덮어쓸 수 있습니다.
- **다른 워크트리** — 저장소 상대경로만 같습니다. 지금은 안전하지만 머지에서 만납니다.

**차단하지 않습니다.** `additionalContext`로 사실만 얹고 판단은 세션에 맡깁니다 — 워크트리를 나눠 정당하게 병행하는 작업까지 막으면 도구가 일을 방해합니다. `permissionDecision`도 일부러 넣지 않습니다. `"allow"`를 주면 권한 프롬프트를 건너뛰는 뜻이 되어, 경고를 붙이려던 훅이 승인 자동화로 변합니다.

보드가 있으면 목록 1행에 겹침 배지(`⚠ N`)가 붙고, 상세 패널에 무엇이 겹치는지 나옵니다.

```
🗂 보드  내 편집 2 · 겹침 1
   40s   services/a/only.py
   40s ⚠ services/shared/util.py ← 15e60983
```

### 설계 메모

- **락이 없습니다.** 세션은 자기 파일(`<sessionId>.tsv`)에만 append하므로 경합이 없습니다 — macOS에 `flock`이 없어서 공유 단일 파일은 애초에 안전하게 못 씁니다.
- **liveness를 조회하지 않습니다.** 시간창(기본 15분)이 그 역할을 합니다. 죽은 세션은 append가 멈춰 자연히 창 밖으로 밀려나므로, 편집마다 `claude agents --json`(~0.4초)을 부를 이유가 없습니다. 반대로 방금 끝난 세션이 남긴 미커밋 변경은 창 안에 있어 여전히 경고 대상입니다.
- **의도는 기록하지 않습니다.** 사용자 지시는 이미 상대 세션의 transcript에 다 있어서, `UserPromptSubmit` 훅을 하나 덜 둡니다.
- **워크트리는 본 저장소로 접힙니다.** 그래서 본체와 워크트리에서 도는 세션들이 하나의 보드에서 서로를 봅니다. `git worktree add`를 저장소 밖에 걸어도 마찬가지입니다.
- 저장소 밖 경로(임시 파일·scratchpad)는 기록하지 않습니다 — 노이즈입니다.

편집 1회에 더해지는 비용은 확인 훅 ~80ms(충돌 있으면 ~115ms)이고, 기록 훅은 `async`라 편집 흐름을 막지 않습니다.

## 요구사항

**macOS 전용입니다.** `stat -f`(BSD), `osascript`, `pgrep`을 씁니다.

| | 비고 |
|---|---|
| `fzf` | `brew install fzf` |
| `claude` CLI | `claude agents --json`이 목록의 원천 |
| `jq` | 최신 macOS는 `/usr/bin/jq` 기본 탑재 |
| iTerm2 | `⏎` 탭 점프와 cursor/codex 상태 감지에 필요. 없으면 경고 후 목록만 동작 |
| `docker` | 선택 — 있으면 상세 패널에 compose 컨테이너가 붙습니다. 없으면 그냥 빠집니다 |

`perl` `awk` `sed` `ps` `stat` `stty` `osascript` `pgrep` `lsof` `sqlite3`는 macOS 기본 탑재라 따로 설치할 게 없습니다. **bash 3.2**(macOS 기본 `/bin/bash`)에서 동작하므로 최신 bash도 필요 없습니다.

`git` 바이너리는 **필요 없습니다.** 브랜치·워크트리·저장소 루트를 `.git` 파일에서 직접 읽습니다 — 폴링이 2초마다 세션 수만큼 도는데 매번 git 프로세스를 띄우지 않기 위해서입니다.

`cursor-agent`와 `codex`는 선택입니다. 떠 있으면 목록에 합류하고, 없으면 그냥 빠집니다.

`agentop`만 실행하면 Claude와 Codex 세션을 함께 표시합니다. Codex 프로세스가 실제 열고 있는 세션 기록에서 모델·승인 정책·샌드박스 정책과 최신 컨텍스트 사용량을 읽습니다. 별도 서버나 실행 플래그는 필요 없습니다. 세션 파일을 확정할 수 없거나 토큰 기록이 아직 없으면 해당 정보는 미상으로 표시합니다.

## 설치

**어디에 clone해도 됩니다.** 본체가 자기 위치를 스스로 찾아 `lib/`를 읽으므로 정해진 경로가 없습니다.

```bash
git clone https://github.com/dowoonlee/agentop.git
cd agentop
./install.sh
```

`install.sh`는 파일을 어디로 복사하지 않고, **clone한 그 자리**를 가리키는 심볼릭 링크만 PATH에 걸어 줍니다. 먼저 요구사항(macOS · fzf · claude · jq · iTerm2)을 점검해 빠진 게 있으면 알려 줍니다.

| 옵션 | 동작 |
|---|---|
| (없음) | PATH 안의 쓰기 가능한 곳에 링크 (없으면 `~/.local/bin`) |
| `--prefix DIR` | 링크를 걸 디렉터리 지정 |
| `--alias` | 링크 대신 셸 설정(`.zshrc` 등)에 alias 추가 |
| `--name NAME` | 실행 이름 변경 (기본 `agentop`) |
| `--uninstall` | 설치한 링크 제거 (등록된 세션 보드 훅도 함께 걷어냅니다) |
| `--hooks` | 세션 보드 훅을 `~/.claude/settings.json`에 등록 |
| `--unhooks` | 등록한 세션 보드 훅만 제거 |

저장소를 다른 곳으로 옮겼다면 디렉터리째 옮긴 뒤 `./install.sh`를 다시 돌리면 링크가 새 위치를 가리킵니다.

설치 스크립트를 쓰지 않아도 됩니다. 직접 실행하거나, 원하는 방식으로 걸어 두면 그만입니다.

```bash
/path/to/agentop/agentop                      # 그냥 실행
alias agentop='/path/to/agentop/agentop'      # alias
ln -s /path/to/agentop/agentop ~/.local/bin/  # 심볼릭 링크 (이중 링크도 따라갑니다)
```

## 어디서 읽나

- `claude agents --json` — 세션 목록·상태
- `~/.claude/sessions/<pid>.json` — `waitingFor` 폴백
- `~/.claude/projects/…/<sid>.jsonl` — 모델, 권한 모드, 컨텍스트 토큰, 서브에이전트, 백그라운드 태스크
- Codex 프로세스가 열고 있는 `rollout-*.jsonl` — 최신 `turn_context`와 `token_count`에서 모델·승인 정책·샌드박스·컨텍스트 사용량을 읽습니다. 캐시 토큰은 입력 토큰에 포함되므로 중복 합산하지 않습니다
- `lsof` + `ps` — 세션이 물고 있는 리스닝 포트(🌐). 목록 폴링마다 각 1회
- `docker ps` — compose 컨테이너(🐳). 캐시 한 벌을 목록·상세가 같이 읽고, 갱신은 백그라운드
- iTerm2 화면 텍스트(AppleScript) — cursor-agent / codex 상태 판정
- `~/.claude/session-board/<저장소>/<sid>.tsv` — 세션 보드(훅이 남긴 편집 기록)

transcript는 수십 MB까지 커지므로 꼬리 256KB만 훑고, 백그라운드 태스크 스캔은 `(크기:mtime)` 서명으로 캐시해 변경된 세션만 다시 읽습니다.
